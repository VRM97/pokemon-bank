# Pokémon Bank API

```lua
local bank = mod.find("vrm_pokemon_bank")
if bank then
  local boxNum, slot = bank.exports.depositPokemon(mon, { game = game })
  local mon2 = bank.exports.withdrawPokemon(boxNum, slot, game)
end
```

`mod.find` returns `nil` when Pokémon Bank isn't installed or is disabled -- always check the handle before calling into `.exports`. Nothing here depends on any particular save/version being active; the Bank's storage is shared across all of them (see README.md's **Where the data lives**).

## Box numbering: read this before storing a `{ box, index }` pair

A box's **number is a snapshot, not a stable id**. By default, the instant a box empties out (its last Pokémon withdrawn, released, or moved away) and it has no name, that box is deleted outright rather than kept as a hole, and every later box's number shifts down by one to fill the space -- a box's own name (see **Persistence** below) shifts down right along with it. The player's own **DELETE EMPTY BOX** option controls this: **UNNAMED** (the default, described above) leaves a *named* empty box in place instead of deleting it, **ALL** deletes every empty box regardless of name (dropping its name too), **NEVER** deletes none automatically -- MANAGE BOX's own **DELETE** action is the manual equivalent for a box a policy of UNNAMED/NEVER would otherwise keep, but only ever on an already-empty box. `boxCount()` is always `(occupied or kept-empty boxes) + 1` -- the `+1` is the one spare empty box every call that can grow the Bank (`depositPokemon`, `movePokemon`) is guaranteed to find room in. MANAGE BOX's own **SWITCH** is the one deliberate exception to the numbering itself: it swaps two box numbers' contents and names outright, on the player's own request.

Practically: don't cache a `{ box, index }` pair across a turn boundary, an event, or any other mod's own deposit/withdraw and expect it to still point at the same Pokémon -- re-resolve it from `listPokemon()` first, or call `getPokemon(box, index)` and compare against what you expect to find there before acting on it (`withdrawPokemon`/`releasePokemon` on a stale pair just does nothing useful -- whatever is actually sitting in that slot by then). This mod's own UI follows the same rule internally.

## Pokémon

Every deposit stamps `mon.originGame` and `mon.originGeneration` the first time that mon enters the Bank. Only set when still `nil`, so a later re-deposit (from a different save or version) never overwrites them. A mon banked before these fields existed carries neither -- `validatePokemonStorage` backfills them for one still missing either, but only when `mon.otId` matches the validating save's own trainer id.

- `depositPokemon(mon, opts)` -- `opts.game`, if given, freezes the mon's stats block before storage. There is no box limit. Returns `boxNum, slotIndex`, or `nil, "invalid pokemon"` for a malformed `mon`.
- `depositPartyPokemon(game, opts)` -- bulk deposit from the player's party to the Bank. `game` is required. `opts.boxNum` specifies the target Bank box (defaults to the last box, which is always empty). `opts.indices` is an array of party indices to deposit (defaults to `2..last`, keeping the first Pokémon). Returns an array of `{ box, index, mon }` for each deposited mon, or `nil, "error message"`. Ensures at least one Pokémon remains in the party. When a box fills, remaining mons continue to the next box.
- `depositBoxPokemon(game, pcBoxNum, opts)` -- bulk deposit from a PC box to the Bank. `game` is required. `pcBoxNum` is the source PC box number (1-12). `opts.boxNum` specifies the target Bank box (defaults to the last box). `opts.indices` is an array of PC box slot indices to deposit (defaults to all). Returns an array of `{ box, index, mon }` for each deposited mon, or `nil, "error message"`. When a box fills, remaining mons continue to the next box.
- `withdrawPokemon(boxNum, index, game, fix)` -- removes and returns the mon table, or `nil` if that slot is empty (see box-numbering caveat above), or `nil, "generation"` when the mon carries a TIME CAPSULE floor (`mon.minGeneration`, see **TIME CAPSULE** below) the active generation doesn't clear, or `nil, "illegal"` when **LEGALITY CHECKS** refuses the mon -- checked on the mon still in its box, so a refusal never removes it first. `game` is optional but strongly recommended: when given, catches the mon in the Pokédex (`seen` + `owned`/`caught`) if it wasn't already -- withdrawing is the only Bank action that can land a mon somewhere new (the party or a PC box), so it's the one that can introduce a species the Pokédex hasn't recorded yet. Without `game`, the withdrawal still happens; only the Pokédex write is skipped. `fix` (default `false`) only matters under **LEGALITY CHECKS**' own **FIX** choice: `true` lets `tryFixLegality` (below) actually correct the mon in place instead of just refusing it, same as **REJECT** would; this mod's own screens ask the player first (see README's own **LEGALITY CHECKS** section) -- a caller that wants the same confirmation has to ask before passing `true` itself, since this stays a plain synchronous call with no dialog of its own. Under **FORCE FIX**, `fix` is ignored entirely -- a failing mon is always corrected in place, the same way it would be had the caller passed `true` under **FIX**.
- `withdrawToParty(game, opts)` -- bulk withdraw from the Bank to the player's party. `game` is required. `opts.boxNum` specifies the source Bank box (defaults to the first non-empty box). `opts.indices` is an array of Bank slot indices to withdraw (defaults to all). `opts.fix` is `withdrawPokemon`'s own `fix` (above), applied to every mon in the batch. Returns `{ withdrawn = [array of { mon }], remaining = count }`, or `nil, "error message"`. Withdraws up to the party's capacity (6 total); any remaining mons stay in the Bank, same as one refused by the TIME CAPSULE floor or **LEGALITY CHECKS** (see `withdrawPokemon` above) -- all three are silently skipped rather than reported individually.
- `withdrawToBox(game, targetPcBoxNum, opts)` -- bulk withdraw from the Bank to a PC box. `game` is required. `targetPcBoxNum` is the destination PC box number (1-12). `opts.boxNum` specifies the source Bank box (defaults to the first non-empty box). `opts.indices` is an array of Bank slot indices to withdraw (defaults to all). `opts.fix` is `withdrawPokemon`'s own `fix` (above), applied to every mon in the batch. Returns `{ withdrawn = [array of { mon, pcBox }], remaining = count }`, or `nil, "error message"`. Fills the target box first, then overflows to subsequent PC boxes; if all PC boxes are full, the TIME CAPSULE floor refuses a mon, or **LEGALITY CHECKS** refuses one, it stays in the Bank the same way.
- `getPokemon(boxNum, index)` -- read-only peek; does not remove.
- `getBox(boxNum)` -- a snapshot copy of one box's slots, indexed `1..boxCapacity()` (`nil` for an empty slot), for a mod that wants to render the Bank as a grid instead of walking `listPokemon()` itself. With **BOX SIZE** at **NO LIMIT** (`boxCapacity()` returns `math.huge`), there's no fixed grid to pad out to -- the copy is exactly as long as the box actually is instead. A copy, not a live reference -- mutating it does nothing to the Bank; call it again after any mutation to see the result. `nil` for a `boxNum` outside `1..boxCount()`.
- `movePokemon(srcBox, srcIdx, destBox, destIdx)` -- relocates within the Bank; landing on an occupied slot swaps the two, landing on an empty slot appends to the destination box (same "all empty grid cells are equivalent, boxes are dense arrays" convention the vanilla PC uses). Returns `true`, or `false` (`"full"` if the destination box is already at `boxCapacity()`).
- `releasePokemon(boxNum, index)` -- removes it for good; returns whether anything was actually there to remove. No confirmation -- this mod's own UI asks first, but the exported call does not.
- `listPokemon()` -- every stored mon, as a flat array of `{ box, index, mon }`.
- `pokemonCount()` -- total Pokémon across every box.
- `isValidPokemon(mon, game)` -- `true` when `mon.species` exists in `game.data.pokemon` (and it isn't an Egg on a Gen 1 save without CRYSTAL_251). Exported so other mods can reuse the same rule before depositing or when building their own Bank UI.
- `isLegal(mon, game)` -- the check behind **LEGALITY CHECKS** (**OFF** by default), ported from PKHeX's Gen1/Gen2 legality checks (source-pkhex/) but re-targeted at this recreation's own extracted game data instead of PKHeX's own tables -- see README.md's **LEGALITY CHECKS** for exactly what's checked and what's deliberately left out (timing/encounter legality, trade evolutions). **Runs `reshapeForActiveGame` on `mon` first** (same as opening STATS already does), so every comparison is against `game`'s own shape/data regardless of which game `mon` was originally deposited from -- this mutates `mon` in place even when the check ends up refusing it (it stays in the Bank, just already reshaped). Returns `true`, or `false, reason` (a short string, for debugging -- `withdrawPokemon`/`withdrawToParty`/`withdrawToBox` only look at the first value). `withdrawPokemon`/`withdrawToParty`/`withdrawToBox` only call it at all while the option isn't **OFF**; exported so another mod can run the same check itself regardless of the option.
- `tryFixLegality(mon, game)` -- attempts to correct an illegal `mon` in place for **LEGALITY CHECKS**' own **FIX** choice: recomputes the level off exp, clamps DVs/Stat Exp back into range (rederiving the HP DV and, on Gen 2, the combined Stat Exp cap), drops any duplicate/unlearnable move and truncates down to 4, resets an out-of-line catch rate, rederives Gen 2's gender/shininess off their own DVs, and strips a held item that can't legitimately be held. Runs `isLegal` first and returns `true` immediately if `mon` already passes; otherwise snapshots it, applies the above, and either leaves it fixed (returns `true`) or restores it exactly as it was and returns `false, reason` -- `mon` is only ever left mutated when the result is `true` (already legal or now fixed), never on a `false`. Some failures have nothing to converge on at all (an unknown species, an Egg's own species/game-support gate, or a moveset that empties out entirely) and are refused immediately without attempting anything. Exported so another mod can offer the same fix (see this mod's own README for why its own screens ask the player first, and API.md's own `withdrawPokemon` entry for the exported withdraw calls' own `fix` parameter).
- `needsLegalityFix(mon, game)` -- `true` only when **LEGALITY CHECKS** is on **FIX** and `mon` currently fails `isLegal` -- `false` under **OFF**/**FORCE FIX**/**REJECT**: **FORCE FIX** corrects a failing mon itself without asking, and **OFF**/**REJECT** never offer to fix anything at all. For a caller that wants to ask the player before calling `tryFixLegality` (or passing `fix = true` into a withdraw call), the same way this mod's own screens do.
- `validatePokemonStorage(game)` -- scans `boxes` and `orphaned.mons` bidirectionally: invalid mons in `boxes` move to `orphaned.mons`, mons in `orphaned.mons` that are now valid append to the last box in `boxes`. Also strips an invalid or blacklisted held item off any mon that otherwise stays valid (into the same item quarantine `validateItemsStorage` uses), backfills a still-valid mon's missing `originGame`/`originGeneration` when its `otId` matches `game.save.player.id` (see **Pokémon** above), assigns a `bankId` to any mon in either list that doesn't have one yet, and runs the move-only quarantine pass described below. Returns `{ changed, quarantined, restored, lostMons, restoredMons, lostItems }` (`lostItems` is the held-item stripping above, `{ id, count }` shaped same as `validateItemsStorage`'s own). Does not mark the Bank dirty itself -- call `validateStorage` (below) if you want the combined pass plus dirty handling.
- `validateTimeCapsuleStorage(game)` -- the same bidirectional pass as `validatePokemonStorage`, but between `timeCapsule` and `orphaned.timeCapsule` (see **Time Capsule** below); no held-item or move scrubbing, since a capsule Pokémon only gets those checks at the moment it's actually withdrawn. Returns `{ changed, quarantined, restored, lostMons, restoredMons }`. Does not mark the Bank dirty itself, same as `validatePokemonStorage`.
- `listInvalidPokemon()` -- every quarantined mon as `{ index, mon }` (a copy of the list; mutating it does nothing to the Bank).
- `invalidPokemonCount()` -- how many mons are in `orphaned.mons`.
- `listInvalidTimeCapsulePokemon()` / `invalidTimeCapsulePokemonCount()` -- the same two, over `orphaned.timeCapsule` instead (see **Time Capsule** below).
- `boxCount()` -- see **Box numbering** above.
- `boxCapacity()` -- slots per box: `getBoxSizeOverride()` when set, otherwise the player's own **BOX SIZE** option (**20**/**30**), or `math.huge` at **NO LIMIT** either way, rather than a magic sentinel -- a plain `#box < boxCapacity()` check works regardless of which one is deciding it. Shrinking it doesn't truncate anything: whatever no longer fits in a box moves to the tail, filling whatever box is currently last and then a fresh one after that, the same rule any deposit already follows.
- `setBoxSizeOverride(value)` -- forces `boxCapacity()` straight past the player's own **BOX SIZE** option: a positive integer for that many slots, `math.huge` for no limit, or `nil` to clear the override and hand the decision back to the option (the default). Takes effect immediately, including the reflow above if it shrinks the effective capacity. Lives only in memory, same as `blacklistItem`. Returns `true`, or `false, "bad request"` for anything else (`0`, a negative number, a fraction).
- `getBoxSizeOverride()` -- the raw override itself (a number, `math.huge`, or `nil`), not `boxCapacity()`'s already-combined effective value -- same reason `getTmItemDepositOverride()` exists below: a caller that wants to force it one way and then put back exactly what was there before.
- `reshapeForActiveGame(game, mon)` -- the cross-generation backfill this mod's own `withdrawPokemon`/`withdrawToParty`/`withdrawToBox` already run before a mon leaves the Bank: collapses `exp`/`experience` down to whichever one the active generation reads (never both), translates `status` between Gen 1 and Gen 2 (Gen 2's `toxic` degrades to plain `PSN` on Gen 1, which has no separate badly-poisoned status; the Gen 2-only `statusTurns`/`toxicCounter` are dropped when heading to Gen 1), collapses CRYSTAL_251's `heldItem`/Gen 2's `item` and Gen 2's `eggSteps`/CRYSTAL_251's `eggCycles` the same way, reshapes Egg moves between `moves`/`eggMoves`, reshapes `moves[i].ppUps`/`maxPp` (see `reshapeMoves` below), and splits/recomputes `stats.specialAttack`/`specialDefense`, backfills `maxHp`/`types`/`catchRate` from `game.data.pokemon`, rolls a `gender` from the Attack DV/`genderRatio` rule when the mon doesn't have one yet (a Gen 1 mon never does), and defaults `happiness`/`pokerus` to `70`/`0` (the same starting values `src.battle.gen2.Mon` itself uses) when the mon doesn't have them yet and the active game actually tracks them -- always on Gen 2, only on Gen 1 with CRYSTAL_251 installed (`heldItem`/`eggCycles` above are its doing too). Left untouched on plain Gen 1: nothing there reads either field. Mutates and returns `mon`. For a mod that moves a Pokémon between generations on its own path (bypassing this mod's withdraw calls entirely), calling this first gets the same treatment instead of reimplementing it.
- `reshapeMoves(game, mon)` -- just the move-PP piece of the above, in case a mod only needs that: Gen 1 keeps a move's bonus PP on `ppUps` and recomputes the cap on every read, Gen 2 stores the raised cap directly on `maxPp` and keeps no `ppUps` counter; this fills in whichever field the active generation expects from whichever one the mon already carries. Mutates `mon.moves` in place; returns nothing.
- `reshapeStatus(mon)` -- just the status piece of the above, in case a mod only needs that: translates `mon.status` between Gen 1's `SLP`/`PSN`/`BRN`/`FRZ`/`PAR` and Gen 2's `sleep`/`poison`/`burn`/`freeze`/`paralyze` (Gen 2's `toxic` degrades to plain `PSN` on Gen 1; the Gen 2-only `statusTurns`/`toxicCounter` are dropped when heading to Gen 1). Takes no `game` -- it only needs `GameVersion.generation()`. A no-op when `mon.status` is already `nil`. Mutates `mon` in place; returns nothing.
- `healBank(game)` -- heals every Pokémon currently stored in the Bank in place: full HP, status cleared, every move's PP restored to its current-generation cap. `game` is required. Returns how many mons were healed; marks the Bank dirty when it healed at least one. This is what the **AUTO HEAL** option's **AT POKéMON CENTER** choice calls.
- `registerDex(game, species)` -- marks `species` seen and owned/caught in `game`'s own Pokédex (whichever field name the active generation uses). A no-op without a Pokédex on the save. Exported so a mod that lands a Pokémon in the player's game some other way (TIME CAPSULE below is the one built-in caller besides `withdrawPokemon`/etc themselves) can mark it the same way a normal withdraw already does.

## TIME CAPSULE

Governed by the **STORAGE MODE** option, three choices: **BANK** (default) opens the POKéMON tab straight into **MANAGE PKMN**, exactly as before this option existed -- TIME CAPSULE doesn't show at all. **TIME CAPSULE** opens straight into the capsule instead -- MANAGE PKMN doesn't show at all in this mode, no chooser either. **BOTH** opens a **MANAGE PKMN**/**MANAGE BOX**/**TIME CAPSULE** chooser -- MANAGE BOX only gets its own row in this one case (a shortcut to `openManageBoxList`, the same box manager MANAGE PKMN's own START opens), since otherwise reaching it now costs one extra hop through MANAGE PKMN. TIME CAPSULE lives in the Bank's own `storage.lua` as `s.timeCapsule` -- a flat list of Pokémon with no boxes, since nothing about it needs them. `validateTimeCapsuleStorage` (see **Pokémon** above) quarantines one the currently loaded game no longer recognizes into `s.orphaned.timeCapsule`, the same way `validatePokemonStorage` does for `boxes`/`orphaned.mons`, and the main `validateStorage` pass runs it on every load. Simulates the real Gen 1 -> Gen 2 Time Capsule one-way: a Pokémon deposited from an earlier generation's save can only ever be withdrawn into a **later** one, never back down, and only the one direction this project currently has two generations for is possible at all (Gen 1 -> Gen 2).

That "later" comparison is `mon.minGeneration` -- **not** the highest generation a Pokémon has reached, but the lowest one it's still allowed to withdraw INTO (a floor, not a ceiling). TIME CAPSULE deposit sets it to the depositing save's own generation **plus one** (there's nothing to check yet -- the trip hasn't happened); a successful withdraw then sets it to the destination's own generation, so a further hop (once this project has a Gen 3) has to clear that new floor in turn. Withdrawing is refused whenever the *current* generation is less than this field. It's untouched by the general Bank's own, deliberately unrestricted, cross-generation storage, so it survives a Pokémon drifting back into an earlier-generation save through `depositPokemon`/`withdrawPokemon` -- a re-deposit into TIME CAPSULE from that earlier save still sets the same floor it would have the first time, since the depositing generation hasn't changed. The floor is also enforced on that general Bank side: `withdrawPokemon`/`withdrawToParty`/`withdrawToBox` (see **Pokémon** above) refuse a mon whose `minGeneration` the active generation doesn't clear, the same way TIME CAPSULE's own withdraw does -- otherwise MANAGE PKMN would be a free bypass for the exact same restriction.

The player's own **LEGALITY CHECKS** option (see below) gates TIME CAPSULE too, on both ends: a Pokémon that couldn't legitimately withdraw straight into a game (`isLegal`, below) is refused at TIME CAPSULE deposit as well as withdraw, on top of every generation/species/move/held-item check that always applies regardless of the option. On **FIX**/**FORCE FIX**, only the withdraw side offers to correct it (**FIX** after asking, **FORCE FIX** immediately -- see WITHDRAW PKMN below) -- deposit still just refuses it outright, same as **REJECT**.

- `openTimeCapsuleMenu(game)` -- pushes the DEPOSIT PKMN/WITHDRAW PKMN menu directly, bypassing **STORAGE MODE**'s own **BOTH** chooser gate (same convention `openPokemonMenu`/etc already follow for **SHOW IN PC MENU**). Works regardless of the current **STORAGE MODE** choice -- even **BANK**, where the POKéMON tab itself never reaches it. Returns whatever `mod.ui.push` returns, or `nil, "no game"` without one.
- `timeCapsuleScreenId` -- the registered screen id (`mod.content.screens`) behind that menu, for a mod that wants to push it through its own navigation.
- `timeCapsuleWithdrawScreenId` -- identifies the WITHDRAW PKMN list screen (not a `mod.content.screens` id -- pushed straight onto `game.stack`, same as LINK's own screens), for a `screen.pushed` listener that wants to recognize it.
- `isTimeCapsuleEnabled()` -- `true` when **STORAGE MODE** is **TIME CAPSULE** or **BOTH**, read-only (the option lives inside this mod's `mod.options`, which `mod.find()` doesn't expose).
- `timeCapsulePokemonCount()` -- how many Pokémon are currently sitting in the capsule.
- `listTimeCapsulePokemon()` -- every one of them, as a flat array of `{ index, mon }` (a copy; mutating it does nothing to the capsule).

DEPOSIT PKMN browses BANK/PARTY/PC (same picker `openPokemonPicker` below is built from) and refuses a Pokémon that's an Egg or holds an item, refuses *everything* while the currently active game is already at this project's highest supported generation (nowhere further for anything to go from there, regardless of any one Pokémon's own `mon.minGeneration`), or fails `isLegal` while **LEGALITY CHECKS** isn't **OFF**. WITHDRAW PKMN lists the capsule's own flat contents; picking one offers **TO BANK**/**TO PARTY**/**TO PC** (**TO BANK** hidden under **STORAGE MODE** = **TIME CAPSULE**, matching the POKéMON tab itself in that mode), **STATS** and **RELEASE**, same row shape as MANAGE PKMN's own (see **UI** below) minus **SWITCH** -- there's nothing to switch with, the capsule has no boxes. **TO PC** lands straight in the player's own current PC box rather than asking which one; **START** still opens a box picker for every currently-eligible Pokémon in the capsule at once (PC-only under that same **STORAGE MODE**), picking the destination box just the one time. **RELEASE** fires `pokemon_released` (below) same as any other release, with `box = nil` since the capsule has none. A Pokémon that clears the generation floor has its species and every one of its moves translated to the destination's own ids (`translateSpeciesId`/`translateMoveId` below) **whether or not** a later check in that same pass still refuses it -- `isLegal` needs them translated to look anything up at all, and this mirrors how `isLegal` itself already reshapes a Pokémon it ends up refusing (see its own entry above). The translated species must exist in the destination's own data, every move must be `canLearn`-legal there, and `isLegal` itself must pass unless **LEGALITY CHECKS** is **OFF**; on **FIX**, a Pokémon `isLegal` refuses is offered a fix instead of an outright refusal -- picking a destination for a single Pokémon asks once, **START** asks once for the whole batch (after asking whether to transfer everything at all) -- and only actually leaves the capsule once `tryFixLegality` (above) confirms it. Any refusal (including a declined or failed fix) leaves the Pokémon in the capsule, already translated. One that clears everything and doesn't already hold an item is stamped with one deterministically on deposit and applies it on withdrawal, mirroring the real cart's own Gen1->Gen2 quirk: the species' Gen 1 catch rate byte is reused as a Gen 2 item index (`mon.timeCapsuleItemByte`, resolved at withdrawal against the destination's own `game.data.items[id].index`), with a fixed table converting the handful of catch rates that land on glitch/key-item slots into a real item instead, and Yellow substituting a different byte for PIKACHU/KADABRA/DRAGONAIR/DRAGONITE.

## Items

- `depositItem(id, qty, game)` -- `game` is optional but strongly recommended: without it, only the `HM_`/`TM_` id prefixes and anything added through `blacklistItem` are checked -- no `game.data.items` lookup means the key-item flag can't be (Gen 1's `def.keyItem` or Gen 2's `def.pocket == "KEY_ITEM"`). Returns `true`, or `false, "blacklisted"/"is_tm"/"bad request"`. A `TM_`-prefixed id is refused with `"is_tm"` rather than blacklisted while the MOVES tab is on -- deposit it through `depositMove` (below) instead; this only gates new deposits, a TM already in the Bank as an item from before this rule is untouched. With the MOVES tab off (the player's own **MOVES MENU** option or `setMovesTabEnabled(false)`), a TM deposits as a plain item instead, since there's nowhere else for it to go right now.
- `withdrawItem(id, qty)` -- decrements the Bank's own count only. Does **not** touch any bag -- add it to whatever inventory you mean with your own `Bag.add` first (check its return value before calling this, so a failed add doesn't still remove the item from the Bank -- mirrors what this mod's own UI does).
- `tossItem(id, qty)` -- same effect as `withdrawItem` (decrements the Bank's own count), for when the item is meant to just disappear rather than land in a bag -- fires `item_tossed` instead of `item_withdrawn` so a listener can tell the two apart. Returns `true`, or `false, "not enough"`.
- `itemCount(id)`
- `listItems()` -- a plain `{ id = count }` table (a copy; mutating it does nothing to the Bank).
- `isValidItem(id, game)` -- `true` when `id` is a non-empty string present in `game.data.items`. Exported for other mods.
- `validateItemsStorage(game)` -- scans `items` and `orphaned.items` bidirectionally: unknown ids *and* blacklisted ones (`isBlacklisted`, i.e. an HM/key item) move to `orphaned.items`; ids in `orphaned.items` merge back into `items` only if they're both known and not blacklisted -- a quarantined HM/key item stays quarantined even after it becomes otherwise valid. Returns `{ changed, quarantined, restored, lostItems, restoredItems }` (counts are total item quantities, not distinct ids).
- `listInvalidItems()` -- a plain `{ id = count }` copy of the quarantined stacks.
- `invalidItemCount(id)` -- total quarantined quantity for one id, or across every id when `id` is omitted.
- `isBlacklisted(id, game)` -- true for HMs, key items (needs `game` to check Gen 1's `keyItem` flag or Gen 2's `pocket == "KEY_ITEM"`), and anything added through `blacklistItem`.
- `blacklistItem(id)` -- adds `id` to the Bank's deposit blacklist, on top of the built-in HM/key-item rule. Additive only -- there is no way to lift the built-in rule for either. Lives only in memory: a mod that needs an id blacklisted calls this itself, every load (matches how `mod.options`/manifest declarations already work -- nothing here is a one-time registration that outlives the calling mod being loaded).
- `setTmItemDepositAllowed(value)` -- forces `depositItem`'s own TM-vs-MOVES-tab rule one way or the other, overriding whatever the MOVES tab's own state would otherwise decide: `true` always lets a TM deposit as a plain item, `false` always refuses it, `nil` clears the override and hands the decision back to the MOVES tab (the default). Lives only in memory, same as `blacklistItem`. Returns `true`.
- `isTmItemDepositAllowed()` -- the read side: whether a TM would deposit as a plain item right now, combining the override above (if any) with the MOVES tab's own state.
- `getTmItemDepositOverride()` -- the raw override itself (`true`/`false`/`nil`), not `isTmItemDepositAllowed`'s computed effective value. For a caller that wants to force it one way and then put back exactly what was there before -- `nil` included, which a captured effective boolean can't tell apart from an explicit `false` -- rather than just turning it back off (LINK's own `depositItemSafe` does this around every deposit, so a TM already sitting as a plain item on either side of a transfer never gets quarantined over this side's own MOVES tab).

## Moves
- `depositMove(id, qty)` -- adds `qty` banked uses of move `id`. Does **not** validate `id` against any game data, and does **not** touch any bag -- remove the matching TM stack from wherever you mean yourself first (mirrors what MANAGE MOVES' own **BAG** page's **DEPOSIT** does, which only ever offers a move that's real). Returns `true`, or `false, "bad request"` for a bad `id`/`qty <= 0`.
- `withdrawMove(id, qty)` -- decrements the Bank's own count only. Does **not** touch any bag -- add `qty` of `tmItemForMove(id)` to whatever inventory you mean with your own `Bag.add` first (check its return value before calling this, so a failed add doesn't still remove the use from the Bank -- mirrors `withdrawItem`). Doesn't itself check `isValidMachine` -- MANAGE MOVES' own **BANK** page lists every banked move but refuses a **WITHDRAW** that fails it before ever calling this (below), and a mod calling `withdrawMove` directly is expected to check it too.
- `tossMove(id, qty)` -- same effect as `withdrawMove` (decrements the Bank's own count), for when the move is meant to just disappear rather than land in a bag as a TM -- fires `move_tossed` instead of `move_withdrawn` so a listener can tell the two apart. Returns `true`, or `false, "not enough"`.
- `moveCount(id)`
- `listMoves()` -- a plain `{ id = count }` table (a copy; mutating it does nothing to the Bank).
- `isValidMachine(id, game)` -- `true` when `id` is a known move in `game.data.moves` **and** the active game's `game.data.items` still carries the matching `"TM_" .. id` item. This is narrower than what keeps a move banked at all (see `validateMovesStorage`): this mod's own **WITHDRAW MOVE** row lists every banked move but checks this before opening the quantity prompt, refusing with a message on a `false` instead. Exported for other mods that want the same "can become a TM right now" rule.
- `validateMovesStorage(game)` -- scans `moves` and `orphaned.moves` bidirectionally, but by a narrower rule than `isValidMachine`: only a move id the active game doesn't recognize **at all** (`game.data.moves[id]` missing -- an uninstalled mod, a different version) is quarantined to `orphaned.moves`; one still recognized moves back if it had been. A move that's still real but currently has no TM stays banked and listed either way -- WITHDRAW MOVE just refuses picking it (see `isValidMachine` above). Also fills any empty move slot on any mon in the Bank, the party or a PC box straight from `orphaned.monMoves` (see `validatePokemonStorage` above) for whatever it's newly valid again, the same thing this mod's own **RELEARN MOVE** row does by hand -- never touching a full moveset, which is why RELEARN MOVE still exists for those. Returns `{ changed, quarantined, restored, lostItems, restoredItems, monMovesRestored }` (counts are total banked uses, not distinct ids, except `monMovesRestored` which counts individual moves filled in this way; `lostItems`/`restoredItems` use the same `{ id, count }` shape `validateItemsStorage` does, since a banked move and a banked item both ultimately came from the same TM).
- `listInvalidMoves()` -- a plain `{ id = count }` copy of the quarantined uses.
- `invalidMoveCount(id)` -- total quarantined uses for one move id, or across every id when `id` is omitted.
- `tmItemForMove(id)` -- the TM item id (`"TM_" .. id`) a move converts to/from. Does not check that item actually exists in the active game -- pair with `isValidMachine` first if that matters.
- `canLearn(game, mon, moveId)` -- `true` when `mon`'s own species, or any species it evolved from, could ever learn `moveId` (level-up, TM/HM, or, on Gen 2, an egg move) -- at any level, not a specific one. `false` for an Egg. The same rule TEACH MOVE's own picker filters by, and `isLegal` (above) reuses for its own move check.
- `speciesKnowsMove(def, moveId)` -- the single-species half of `canLearn` above: `true` when `def` (a `game.data.pokemon[species]` record) itself knows `moveId`, with no prevolution walk.
- `prevolutionOf(game, species)` -- the species one level-up/evolution away from evolving into `species`, or `nil` for one nothing evolves into. Cached per active game.

## Money

Same asymmetry as `depositItem`/`withdrawItem`: these only change the Bank's own balance. Neither touches the save's own wallet (`game.save.money` on Gen1, `game.save.player.money` on Gen2) -- debit/credit whatever wallet you mean yourself (mirrors what this mod's own DEPOSIT MONEY/WITHDRAW MONEY do, which already branch on `GameVersion.generation()` to hit the right field).

- `bankMoney()` -- the Bank's own money balance, independent of any save's wallet.
- `depositMoney(amount)` -- adds `amount` to the Bank's balance. Returns `true`, or `false, "bad request"` for an `amount <= 0`.
- `withdrawMoney(amount)` -- subtracts `amount` from the Bank's balance. Returns `true`, or `false, "not enough"` for an `amount <= 0` or greater than `bankMoney()`.
- `maxMoney` -- `999999`, the game's own money cap. Not enforced by `depositMoney`/`withdrawMoney` themselves (the Bank's own balance is a plain number, uncapped) -- only relevant if you're about to add the withdrawn amount to the save's wallet, the same way this mod's own WITHDRAW MONEY caps itself against it first.

## Persistence

Every export above that mutates the Bank only changes the in-memory copy -- the actual write to `storage.lua` is deferred to line up with the game's own save (a `save.write` hook), not flushed immediately. This is deliberate: see README.md's **Where the data lives** for why an immediate write would let a reset-without-saving duplicate whatever was just deposited. Nothing to do differently here -- just don't assume a mutation is durable the instant the call returns.

On every `save.loaded`, this mod runs `validateStorage(game)` automatically (Pokémon + items + moves) and, per the player's **REPORT MODE** option, shows the full REPORT screen, a short MESSAGE text box, or nothing at all when anything moved -- plus a separate notice if `recoveredMoney` came back positive. Other mods can call the validation exports directly at any time.

`storage.lua` is **version 5**: `{ version, boxes, boxNames, currentBox, items, moves, money, storageId, orphaned = { mons, items, moves, monMoves } }`. Loading a lower version file migrates it and marks the Bank dirty so the upgraded shape is written on the next save. A mon's `bankId` is rolled at random (collision-checked against every one already in use); `storageId` is the Bank *itself*'s own id -- one per Bank instance rather than per mon, rolled once the first time anything asks for it and kept from then on (not part of the version-5 migration, same as `bankId` isn't -- both are assigned lazily, on first read/validate, rather than through a storage version bump). `boxNames` is a sparse `{ [boxNum] = name }` map, only holding entries for boxes MANAGE BOX's own **RENAME** has actually named -- not exposed through `mod.exports`, since it's this mod's own UI-only concern. A PC box's own name is a separate overlay, kept in this save's own `modData` instead (key `pc_box_names`, same sparse shape) rather than in the Bank -- the PC itself lives inside the save, not the Bank, so each save/player keeps its own set instead of sharing one globally.

- `validateStorage(game)` -- the combined pass this mod runs on load: calls `validatePokemonStorage`, `validateTimeCapsuleStorage`, `validateItemsStorage` and `validateMovesStorage`, marks the Bank dirty when any reports `changed`. Returns `{ changed, pokemon, timeCapsule, items, moves, recoveredMoney, report }` -- `pokemon`/`timeCapsule`/`items`/`moves` are exactly what those four calls themselves returned; `recoveredMoney` is a stray Gen 2 `save.money` this pass found and moved into the Bank, if any (see **Money** above); `report` is `{ lostMons, lostItems, restoredMons, restoredItems }`, merging every lost/restored Pokémon, item and banked move from all four passes into the one combined list this mod's own REPORT MODE reads. Returns `nil` without a `game`.
- `flush()` -- forces the pending write immediately instead of waiting for the next save. Returns whether anything was actually pending. Normally unnecessary; reach for it only when a mod has its own reason a Bank change must be durable before the game's own save point (e.g. right before code that risks the process, like a native file-picker call).
- `getStorageId()` -- this Bank's own persistent id (a number), assigning one on first call if it doesn't have one yet (marking the Bank dirty when it does). Not a security measure -- a copied `storage.lua` carries this id right along with everything else in it, and it's checked as plain data over LINK the same way `storageVersion` is -- just something LINK (below) can compare to tell two genuinely different Banks apart from a save copied onto another account.

## Cross-generation ids

A handful of species/item ids the extractor gives a *different* string in Gen 1 than in Gen 2 for the exact same thing -- everything else already shares one id across both (moves especially: every Gen 1 move keeps the same id **and** numeric index in Gen 2).

- `translateSpeciesId(id, targetGen)` -- `MR_MIME`/`MR__MIME` and `FARFETCHD`/`FARFETCH_D` translate to each other; any other id (the overwhelming majority) comes back unchanged, so this is safe to call on every species id rather than only ones already known to need it. `targetGen` defaults to `GameVersion.generation()`, i.e. the id spelled the way the game currently running wants it.
- `translateItemId(id, targetGen)` -- `THUNDER_STONE`/`THUNDERSTONE` translate to each other; any other id comes back unchanged, same as above.
- `translateMoveId(id, targetGen)` -- always returns `id` unchanged today: every Gen 1 move keeps the same id (and numeric index) in Gen 2. Kept alongside the two above for a future re-review to fill in, if a later data extractor change ever introduces a mismatch.

## Statistics

Every deposit, withdrawal, release, teach, item/money transfer and LINK exchange is tallied two ways: an all-time total shared by every save that ever used this Bank (`stats.lua`, next to `storage.lua`), and a per-save total scoped to just the active playthrough (written into that save's own `modData`, so it travels and rewinds with the save). Both share the same shape: `{ transactions, pokemon = { deposited, withdrawn, released }, items = { depositedOps, depositedQty, withdrawnOps, withdrawnQty, tossedOps, tossedQty }, moves = { depositedOps, depositedQty, withdrawnOps, withdrawnQty, taught }, money = { depositedOps, depositedTotal, withdrawnOps, withdrawnTotal }, link = { completed, cancelled, sent = { pokemon, items, moves, money }, received = { pokemon, items, moves, money } } }`.

- `getBankStats()` -- the all-time totals above, plus `peakMoney` (the Bank's own highest-ever balance) and `species` (a `{ speciesId = timesDeposited }` table). A copy, not a live reference.
- `getSaveStats()` -- the active save's own contribution to those same totals, without `peakMoney`/`species` (those only mean something at the shared-Bank level). A copy, not a live reference.
- `statsScreenId` -- the registered screen id (`mod.content.screens`) behind the **VIEW STATS** row on the OPTIONS > POKéMON BANK page (see README.md), for a mod that wants to push it through its own navigation.

DELETE DATA resets the all-time totals along with everything else in the Bank; a save's own totals aren't part of that, since they live in the save, not the Bank.

## PC menu entry

Pokémon Bank adds a **POKéMON BANK** row to the PC's own main menu (the one offering BILL's PC / Player's PC / PROF.OAK's PC / LOG OFF) through the `ui.pc.items` hook. Two independent ways to control it:

- `setPcEntryEnabled(enabled)` -- pass `false` to hide the row outright regardless of the player's own **SHOW IN PC MENU** option, `true` (or call again) to restore it. Meant for a mod that replaces the PC flow entirely and wants to fold the Bank's entry point into its own UI instead of showing both.
- `pcMenuLabel` -- the exact row label (`"POKéMON BANK"`), for a mod that would rather remove it itself with `mod.ui.removeLabel` inside its own `ui.pc.items` hook (registered with a higher `priority` than this mod's manifest `priority`, so it runs after -- see the engine's decorate-after-`next` hook convention). `setPcEntryEnabled` above is the simpler option for most cases; this is for a mod that wants to make that decision per-call (e.g. only inside its own replacement PC screen) rather than as a standing on/off switch.
- `setPokemonTabEnabled(enabled)` / `setItemsTabEnabled(enabled)` / `setMovesTabEnabled(enabled)` / `setMoneyTabEnabled(enabled)` -- same idea as `setPcEntryEnabled`, one level down: hide (`false`) or restore (`true`, or call again) just the POKéMON, ITEMS, MOVES or MONEY side, independent of the player's own **POKéMON MENU** / **ITEMS MENU** / **MOVES MENU** / **MONEY MENU** options (each combines the same way `setPcEntryEnabled` and **SHOW IN PC MENU** already do -- both the option and the API flag have to allow a tab for it to show). With only one tab enabled (by either mechanism), the **POKéMON BANK** row -- and `openBankMenu` below, which is the same chooser -- skips the chooser and opens that tab directly; with none enabled, the row doesn't appear at all and `openBankMenu` returns `false`. Doesn't affect `open(game, tab)`, `openPokemonMenu`/`openItemsMenu`/`openMovesMenu`/`openMoneyMenu`, `pokemonScreenId`, `itemsScreenId`, `movesScreenId` or `moneyScreenId` below -- those stay reachable regardless, the same way `open` already bypasses **SHOW IN PC MENU**/`setPcEntryEnabled`.
- `isPcEntryEnabled()` / `isPokemonTabEnabled()` / `isItemsTabEnabled()` / `isMovesTabEnabled()` / `isMoneyTabEnabled()` -- the read side of the setters above. The player's own **SHOW IN PC MENU** / **POKéMON MENU** / **ITEMS MENU** / **MOVES MENU** / **MONEY MENU** options live inside this mod's `mod.options`, which `mod.find()` does not expose (it only hands back `{ id, version, exports }`) -- these are the only way for another mod to know whether a side is actually visible right now. Each returns the already-combined result (the player's option **and** whatever any mod's setter above last chose), the same value the **POKéMON BANK** PC row itself decides with.

## UI

- `openItemsMenu(game)` / `openMovesMenu(game)` / `openMoneyMenu(game)` / `openPokemonMenu(game)` -- pushes that one tab's own screen directly, no PC or top-level POKéMON/ITEMS/MOVES/MONEY/LINK chooser required, so another mod can offer any single tab from its own menu. POKéMON's own screen is entirely shaped by **STORAGE MODE**: MANAGE PKMN directly on **BANK**, TIME CAPSULE directly on **TIME CAPSULE** (MANAGE PKMN doesn't show at all in that mode), or a **MANAGE PKMN**/**MANAGE BOX**/**TIME CAPSULE** chooser on **BOTH** -- the same shape MOVES' own screen already uses for its **MANAGE MOVES**/**RELEARN MOVE** chooser. Call `openTimeCapsuleMenu` (above) instead for a mod that wants to reach TIME CAPSULE regardless of the current mode, including **BANK**. Returns whatever `mod.ui.push` returns, or `nil, "no game"` without one.
- `openBankMenu(game)` -- the main **POKéMON BANK** entry point itself: the same POKéMON/ITEMS/MOVES/MONEY chooser the PC's own **POKéMON BANK** row opens (skipping straight to that one tab, same as the row, when only one is enabled by `setPokemonTabEnabled`/etc and the player's own options). Lets another mod offer this mod's whole entry point from its own menu without routing through a PC. Returns `true` once it's opened something, `false` when every tab is off and there was nothing to open (the row itself just wouldn't appear at all in that case), or `nil, "no game"` without a `game`.
- `open(game, tab)` -- a thin dispatcher over the four `openXxxMenu` calls above by name; `tab` is `"pokemon"` (default), `"items"`, `"moves"` or `"money"`. Kept for existing callers -- a new one is better off calling the named export directly.
- `pokemonScreenId`, `itemsScreenId`, `movesScreenId`, `moneyScreenId` -- the registered screen ids (`mod.content.screens`) backing the four tabs, for a mod that wants to push them through its own navigation instead of `open`/`openXyzMenu`. Pushing `pokemonScreenId` is exactly `openPokemonMenu` -- both go through the same registered factory, chooser included.

## LINK

- `openLinkMenu(game)` -- pushes the LINK connect screen, same as its own PC-menu row. Returns whatever `game.stack:push` returns, or `nil, "no game"` without one. Ignores the player's own **LINK MENU** option and `setLinkTabEnabled` below -- same convention as `openPokemonMenu`/etc, which bypass **SHOW IN PC MENU**/`setPcEntryEnabled` too.
- `linkScreenId` -- **not** a `mod.content.screens` id (unlike `pokemonScreenId`/etc): LINK's screens are pushed straight onto `game.stack`, like **Pickers** below, so there's nothing to push it *through*. Present for identification only (e.g. a `screen.pushed` listener checking what's on top).
- `setLinkTabEnabled(enabled)` / `isLinkTabEnabled()` -- same idea as `setPokemonTabEnabled`/etc: hide (`false`) or restore (`true`) the LINK side independent of the player's own **LINK MENU** option.

## Pickers

Four standalone browsing screens for a mod that wants the same SELECT-cycles-storages/Left-Right-flips-boxes browsing without reimplementing it. Each pushes a screen and returns a **handle**, `{ refresh, setFooter, close }`, instead of the picked value directly -- picking happens later, through `opts.onChoose`, possibly much later if that callback itself waits on a further screen (a forget-a-move prompt, a confirmation) -- `handle.refresh()` rebuilds the row list and resets the footer to its default hint, `handle.setFooter(msg)` is `list.footer = msg`, `handle.close()` pops the screen. None of the four assume anything about *why* a mon/box/item/move was picked -- no TO BANK/SWITCH/RELEASE/TOSS submenu is offered after a pick, since that is this mod's own business logic, not something a caller wants assumed for them; `opts.onChoose` is the only thing that runs.

Every `hideX` option defaults to `false` (that view shown); hiding every view for a picker returns `nil, "no views enabled"` instead of pushing anything, and hiding all but one still opens normally with SELECT simply doing nothing (nowhere left to cycle to). `game` is required by all four; omitting it returns `nil, "no game"`.

- `openPokemonPicker(game, opts)` -- browse one Pokémon at a time across the Bank, the party and a PC box. `opts.hideBank`/`opts.hideParty`/`opts.hidePc`, `opts.startView` (`"bank"`/`"party"`/`"pc"`), `opts.rowRight(mon, view, boxNum, index)` (return a string for the row's second line, or `nil` for none), `opts.onChoose(mon, { view, box, index })` (`box` is `nil` on the `"party"` view), `opts.onCancel()`, `opts.title(view, boxNum)`, `opts.footer(view, nextViewLabelOrNil)`. Each row has room for only one second line: setting `opts.rowRight` replaces the level that would otherwise show there.
- `openMovePicker(game, opts)` -- identical to `openPokemonPicker`, except the second line is always **ABLE**/**---** from a required `opts.compatible(mon)` instead of `opts.rowRight` (which this one doesn't take) -- the same annotation TEACH MOVE/RELEARN MOVE show, for a mod with its own idea of what a Pokémon needs to be "compatible" for. Returns `nil, "opts.compatible required"` without one. `---` rather than vanilla PartyMenu's own `NOT ABLE`: this picker is one row per Pokémon, not PartyMenu's two-row entry, and `NOT ABLE` didn't fit the line.
- `openItemPicker(game, opts)` -- browse one item stack at a time across the Bank, the Bag and the player's PC items. `opts.hideBank`/`opts.hideBag`/`opts.hidePc`, `opts.startView` (`"bank"`/`"bag"`/`"pc"`), `opts.rowRight(id, count, view)` (default `"x"..count`), `opts.onChoose(id, count, view)`, `opts.onCancel()`, `opts.title(view)`, `opts.footer(view, nextViewLabelOrNil)`. The Bag view lists in real Bag order (the same order MOVE ITEM's own SWITCH reorders); Bank and PC both list alphabetically.
- `openBoxPicker(game, opts)` -- browse a *whole* box at a time across the Bank and a PC box (no Bag/party equivalent -- boxes only exist on those two sides); A confirms whichever box is currently on screen rather than picking a row within it. `opts.hideBank`/`opts.hidePc`, `opts.startView` (`"bank"`/`"pc"`), `opts.requireNonEmpty` (bool, default `true` -- an empty box shows `opts.emptyMessage` instead of calling `onChoose`), `opts.onChoose(view, boxNum)`, `opts.onCancel()`, `opts.title(view, boxNum)`, `opts.footer(view, boxNum, nextViewLabelOrNil)`. A caller that wants a source-then-destination flow of its own (mirroring this mod's own TRANSFER BOX) just calls this twice.

## Events

Every deposit, withdraw, release, teach and item/money transfer -- through this mod's own UI or through the exports above -- fires one of:

- `mod.vrm_pokemon_bank.pokemon_deposited` -- `{ box, index, mon }`
- `mod.vrm_pokemon_bank.pokemon_withdrawn` -- `{ box, index, mon }`
- `mod.vrm_pokemon_bank.pokemon_released` -- `{ box, index, mon }` (`box` is `nil` for a TIME CAPSULE release -- it has none)
- `mod.vrm_pokemon_bank.item_deposited` -- `{ id, qty }`
- `mod.vrm_pokemon_bank.item_withdrawn` -- `{ id, qty }`
- `mod.vrm_pokemon_bank.item_tossed` -- `{ id, qty }`
- `mod.vrm_pokemon_bank.move_deposited` -- `{ id, qty }`
- `mod.vrm_pokemon_bank.move_withdrawn` -- `{ id, qty }`
- `mod.vrm_pokemon_bank.move_tossed` -- `{ id, qty }`
- `mod.vrm_pokemon_bank.move_taught` -- `{ id, mon }`
- `mod.vrm_pokemon_bank.money_deposited` -- `{ amount }`
- `mod.vrm_pokemon_bank.money_withdrawn` -- `{ amount }`
- `mod.vrm_pokemon_bank.link_completed` -- `{ sent, received }`, once a LINK exchange lands in the Bank (after both sides' second CONFIRM). `sent`/`received` are each `{ pokemon, timeCapsule, items, moves, money }` -- `pokemon`/`timeCapsule` counts, `items`/`moves` summed quantities, `money` a total.
- `mod.vrm_pokemon_bank.link_cancelled` -- `{}`, whenever a LINK session ends any other way (CANCEL, a version mismatch, linking to yourself, a dropped connection) and everything staged to send was handed back.

`mod.events:on("mod.vrm_pokemon_bank.pokemon_deposited", function(payload) ... end)` subscribes the usual way. Remember `box`/`index` in a payload are only a snapshot -- see **Box numbering** above.
